# DIAL 规划与任务拆解模板

> 用于**短期/中期/长期规划**及**任务拆解**，配合 [DIAL 融合方法论](../docs/DIAL.md) 使用。  
> 参考框架：PESTEL、波特五力、SWOT、BIZBOK、BABOK、MIT 九要素。AI 时代可配合 AI 辅助生成。

## 一、短中长期规划

### 1.1 规划总览

| 维度 | 短期（1–3 月） | 中期（3–6 月） | 长期（6–12 月+） |
|------|----------------|----------------|------------------|
| **目标** | MVP、价值验证、可演示 | 商业模式验证、核心闭环 | 增长、壁垒、规模化 |
| **一堂对应** | 需求 + 解决方案 | 商业模式 | 增长 + 壁垒 |
| **交付物** | 可投标/可演示版本 | 可运营、可复购 | 可复制、护城河 |
| **里程碑** | M1、M2 | M3、M4 | M5+ |

### 1.2 短期规划（模板）

| 里程碑 | 时间 | 范围 | 交付物 | 验收标准 |
|--------|------|------|--------|----------|
| M1 | 第 X 周 | 【Epic/REQ】 | 【具体交付】 | 【可演示/可投标】 |
| M2 | 第 X 周 | 【Epic/REQ】 | 【具体交付】 | 【可演示/可投标】 |

### 1.3 中期规划（模板）

| 里程碑 | 时间 | 范围 | 交付物 | 验收标准 |
|--------|------|------|--------|----------|
| M3 | 第 X 月 | 【Epic/REQ】 | 【具体交付】 | 【可运营】 |
| M4 | 第 X 月 | 【Epic/REQ】 | 【具体交付】 | 【可复购】 |

### 1.4 长期规划（模板）

| 里程碑 | 时间 | 范围 | 交付物 | 验收标准 |

## 二、任务拆解结构

### 2.1 层级关系

```
Epic（按 L2 模块）
  └── Story（按 L3 业务动作，1–2 周）
        └── Task（可执行单元，0.5–2 天）
              └── AC（对应 L4 或 Given/When/Then）
```

### 2.2 Epic 拆解模板

| Epic ID | Epic 名称 | 对应 L2 | 包含 REQ | 短期/中期/长期 |
|---------|------------|---------|----------|----------------|
| EPIC-X | 【名称】 | L2-XX | REQ-XXX | 短期 |

### 2.3 Story 拆解模板

| Story ID | 用户故事 | 对应 L3 | 验收标准（AC） | 估算 |
|----------|----------|---------|----------------|------|
| SX.Y | 作为【角色】，我希望【目标】，以便【价值】 | L3-XX-YY | Given/When/Then 或 L4 步骤 | S/M/L |

### 2.4 Task 拆解模板

| Task ID | 任务描述 | 所属 Story | 类型 | 估算 | 负责人 |
|---------|----------|------------|------|------|--------|
| TX.Y.Z | 【具体可执行任务】 | SX.Y | 开发/设计/测试/文档 | Xh | - |

**Task 类型**：开发、设计、测试、文档、对接、调研

## 三、AI 辅助拆解提示词（示例）

### 3.1 五维洞察（PESTEL + 五力 + SWOT）

```
基于以下业务/行业，生成五维洞察初稿：
- 行业：【行业名称】
- 业务方向：【简述】
请按 PESTEL（政治、经济、社会、技术、环境、法律）、波特五力（同业、供应商、购买者、替代品、新进入者）、SWOT（优劣势、机会威胁）结构化输出，每项 2-3 条关键点。
```

### 3.2 从 REQ 拆解 Epic/Story

```
基于以下需求，按 DIAL 方法论拆解为 Epic 和 Story：
- 需求：【REQ 描述】
- 已有 L2 模块：【L2 列表】
- 已有 L3 动作：【L3 列表或部分】
请输出：Epic 列表、每个 Epic 下的 Story 列表，Story 需包含用户故事格式和对应 L3。
```

### 3.3 从 Story 拆解 Task

```
基于以下 User Story，拆解为可执行的 Task：
- Story：【用户故事全文】
- 对应 L3：【L3 动作】
- 技术栈：【如 React、Node 等】
请输出：Task 列表，每项包含描述、类型（开发/设计/测试）、估算（小时）。
```

### 3.4 业务需求类型识别（运营提效 vs 新增业务）

```
基于以下业务场景，识别需求类型并给出数字化提升方向：
- 场景：【描述】
- 当前痛点：【描述】
请输出：1) 需求类型（运营提效/体验提升/新增业务/风险管控/生态协同）；2) 数字化提升方向（参考 MIT 九要素：流程数字化、数据辅助、新触点、新能力等）；3) 可量化指标建议。
```

### 3.5 生成 BML 验证计划

```
基于以下 MVP 范围，制定 Build-Measure-Learn 验证计划：
- MVP 功能：【功能列表】
- 核心假设：【价值假设/增长假设】
请输出：测量指标、数据收集方式、学习判断标准、坚持/转向的决策条件。
```
