# BAM 工作流检查清单

> 用于各 Phase 启动/完成时的自检，确保 BAM 融合流程完整执行。

---

## Phase 1 分析（Analyst）

### 启动前
- [ ] 已获取项目背景、招投标/业务需求
- [ ] 已明确目标用户与核心价值主张

### 进行中
- [ ] 完成项目定位（产品名称、目标用户、核心价值、差异化）
- [ ] 完成市场与需求验证（招投标、行业痛点、场景分析）
- [ ] 明确范围边界（包含/不包含）
- [ ] **定义 L1 一级业务域**（至少 1 个业务闭环）

### 产出
- [ ] Project Brief 文档
- [ ] L1 业务域列表

### 完成标准
- [ ] L1 覆盖业务范围，无遗漏
- [ ] 范围边界清晰，可向 PM 交接

---

## Phase 2 规划（PM）

### 启动前
- [ ] 已收到 Project Brief
- [ ] 已获取 L1 业务域定义

### 进行中
- [ ] 完成用户旅程与角色映射
- [ ] 完成功能需求清单（REQ）及验收标准
- [ ] 完成非功能需求
- [ ] **定义 L2 二级业务流程**（模块/页面级）
- [ ] **建立 REQ ↔ L1 ↔ L2 映射**

### 产出
- [ ] PRD 文档
- [ ] L2 模块列表
- [ ] REQ 与 L2 对应表

### 完成标准
- [ ] 每个 REQ 可追溯至 L1、L2
- [ ] 用户旅程与 L2 模块一一对应
- [ ] 可向 Architect 交接

---

## Phase 3 方案设计（Architect + Scrum Master）

### 启动前
- [ ] 已收到 PRD
- [ ] 已获取 L1、L2、REQ 映射

### 进行中
- [ ] 完成 Epic 划分
- [ ] **建立 Epic ↔ L2 映射**
- [ ] 完成 Story 拆解（JIT 或完整）
- [ ] **建立 Story ↔ L3 业务动作映射**
- [ ] **将 L4 业务步骤作为 Story AC 输入**
- [ ] 完成架构要点（前端/后端/数据/集成）
- [ ] 完成迭代规划

### 产出
- [ ] 架构文档
- [ ] Epic 列表
- [ ] Story 列表

### 完成标准
- [ ] 每个 Epic 可追溯至 L2、REQ
- [ ] 每个 Story 可追溯至 L3
- [ ] Story AC 覆盖关键 L4 步骤
- [ ] 可向 Developer/QA 交接

---

## Phase 4 实施（Developer + QA）

### 启动前
- [ ] 已收到 Epic、Story
- [ ] 已获取 Story ↔ L3、L4 映射
- [ ] 迭代范围已明确

### 进行中
- [ ] 按 Story 实现功能
- [ ] **按 L4 步骤设计/执行验收**
- [ ] 通过 Story AC
- [ ] 通过迭代质量门禁

### 产出
- [ ] 代码
- [ ] 测试
- [ ] 可演示交付物

### 完成标准
- [ ] Story AC 全部通过
- [ ] 关键 L4 步骤可验收
- [ ] 无 P0 缺陷

---

## 通用检查

### 追溯完整性
- [ ] REQ → L1 → L2 → Epic → Story → L3 → L4 链路可追溯
- [ ] 使用 [BAM 追溯矩阵](./BAM-追溯矩阵.html) 核对

### 范围蔓延
- [ ] 新增需求是否在 L1 边界内？
- [ ] 若否，是否已升级至完整 BAM 规划？

### 文档同步
- [ ] BAM-追溯矩阵.json 已更新（如有映射变更）

---

*检查清单随项目实践可增删调整*
