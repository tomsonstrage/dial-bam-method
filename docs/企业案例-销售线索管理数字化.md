# 企业案例：销售线索管理数字化

> 完整案例：从洞察到交付的 BAM 追溯。展示 DIAL-BAM 方法论在 ToB 数字化项目中的落地。

## 一、案例背景

| 维度 | 说明 |
|------|------|
| **行业** | 工业设备制造 |
| **企业规模** | 年营收 3 亿，销售团队 50 人 |
| **痛点** | 线索散落 Excel/微信，转化率难追踪，商机阶段不透明 |
| **目标** | 6 个月内上线线索→商机管理系统，实现全链路可追溯 |

---

## 二、Discovery：洞察与痛点

### 2.1 五维洞察（摘要）

| 维度 | 关键结论 |
|------|----------|
| **PESTEL-政策** | 制造业数字化转型政策支持，补贴可申请 |
| **PESTEL-经济** | 下游客户预算收紧，需提升销售效率降本 |
| **波特五力** | 同业竞争激烈，差异化靠服务与响应速度 |
| **SWOT** | 优势：客户关系好；劣势：销售过程不透明；机会：CRM 成熟；威胁：竞品已上系统 |

### 2.2 痛点画布（痛频量价）

| 维度 | 内容 |
|------|------|
| **痛** | 线索散落、转化率难统计、商机阶段靠人工汇报 |
| **频** | 每日销售跟进、周会汇报、月度复盘 |
| **量** | 50 销售 × 平均 20 线索/月 = 1000 条/月 |
| **价** | 线索流失率约 15%，按客单价 50 万估算，年损失约 750 万 |

### 2.3 需求假设

| ID | 假设 | 验证方式 |
|----|------|----------|
| H1 | 销售愿意在系统中录入线索 | 试点 5 人，2 周使用率 >80% |
| H2 | 主管需要看转化漏斗做分配 | 访谈 3 位主管 |
| H3 | 客户信息集中管理可提升跟进效率 | 对比试点前后平均跟进时长 |

## 三、Insight：战略与商业模式

### 3.1 Project Brief

| 字段 | 内容 |
|------|------|
| **项目背景** | 销售线索散落，转化率难追踪，需数字化统一管理 |
| **目标市场** | 工业设备制造企业销售团队 |
| **价值主张** | 线索→商机全链路可视化，转化率可统计，分配可追溯 |
| **L1 业务域** | 销售管理（线索管理、商机管理） |

### 3.2 商业模式画布（摘要）

| 模块 | 内容 |
|------|------|
| **客户细分** | 制造企业销售团队、销售主管 |
| **价值主张** | 线索集中、转化可视、分配透明 |
| **收入来源** | 软件订阅 + 实施服务 |
