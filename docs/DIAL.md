# DIAL 融合方法论

> ⚠️ **已深度融合**：本文档已拆分为 [01-方法论](01-方法论.md)、[02-Discovery](02-Discovery.md)、[03-Insight](03-Insight.md)、[04-Architecture](04-Architecture.md)、[05-Launch](05-Launch.md)、[06-AI增强与裁剪](06-AI增强与裁剪.md)。建议从 [01-方法论](01-方法论.md) 开始阅读。

---

> **DIAL** = **D**iscovery（发现） + **I**nsight（洞察） + **A**rchitecture（架构） + **L**aunch（交付）  
> 面向 AI 工具与 Vibe coding 的**洞察→战略→业务需求→数字化承载→规划→任务拆解**全链路方法，融合 BMAD、业务流程、一堂五步法、精益创业，并组合 PESTEL、波特五力、BIZBOK、BABOK 等参考框架。

---

## 一、方法概述

### 1.1 融合来源

| 方法论 | 核心贡献 | 在 DIAL 中的体现 |
|--------|----------|------------------|
| **BMAD** | 四阶段（分析→规划→方案→实施）、角色与产出链 | Architecture、Launch 的结构化交付 |
| **业务流程** | L1/L2/L3/L4 四级拆解、业务可追溯 | Architecture 中的业务架构 |
| **一堂五步法** | 需求→解决方案→商业模式→增长→壁垒、痛频量价、假设驱动 | Discovery、Insight、规划中的短中长期 |
| **精益创业** | Build-Measure-Learn、MVP、价值/增长假设、坚持/转向 | 全流程的假设验证与迭代 |
| **AI + Vibe coding** | 自然语言驱动、快速原型、AI 辅助拆解与实现 | Launch 中的任务拆解与开发方式 |

### 1.2 完整流程：洞察先行，需求在后

```
洞察（行业/社会/技术/竞争/内部）→ 战略规划 → 业务需求 → 数字化如何提升
         │                            │            │              │
    PESTEL/五力/SWOT            战略地图/画布    运营提效/新增业务   系统与工具
         ↓                            ↓            ↓              ↓
Discovery（发现）  →  Insight（洞察）  →  Architecture（架构）  →  Launch（交付）
```

### 1.3 DIAL 四阶段

```
Discovery（发现）  →  Insight（洞察）  →  Architecture（架构）  →  Launch（交付）
    │                      │                      │                      │
洞察 + 需求调研        解决方案 + 战略          业务架构 + 规划        任务拆解 + 迭代
    │                      │                      │                      │
PESTEL/五力/痛频量价   画布/MVP 定义         BIZBOK/L1-L4/Epic      Story→Task、BML
```

## 二、Discovery（发现）— 洞察与需求调研

### 2.1 五维洞察（参考：PESTEL、波特五力、SWOT）

| 维度 | 关注点 | 参考框架 | 产出 |
|------|--------|----------|------|
| **行业** | 产业链、价值链、政策、周期 | PESTEL（P/E/S/T/E/L） | 行业地图、机会与约束 |
| **社会** | 人口、消费、文化、趋势 | PESTEL-Social | 社会趋势、需求演变 |
| **技术** | 成熟度、成本、替代性 | PESTEL-Technological | 技术可行性、技术路线 |
| **竞争** | 对手、替代品、新进入者 | 波特五力 | 竞争格局、差异化空间 |
| **内部** | 能力、资源、组织、文化 | SWOT（S/W） | 能力画像、资源约束 |

**PESTEL**：Political, Economic, Social, Technological, Environmental, Legal  
**波特五力**：同业竞争、供应商议价、购买者议价、替代品威胁、新进入者威胁  
**SWOT**：Strengths, Weaknesses, Opportunities, Threats

### 2.2 战略规划（参考：战略地图、商业模式画布）

| 输入 | 战略输出 | 参考框架 |
|------|----------|----------|
| 行业 + 社会 | 目标市场、业务方向、价值主张 | 战略地图 |
| 技术 + 竞争 | 差异化路径、技术路线、能力建设 | 波特五力 + SWOT |
| 内部 | 资源配置、节奏、取舍 | SWOT |

**商业模式画布**：客户细分、价值主张、渠道、客户关系、收入来源、核心资源、关键活动、关键合作、成本结构

### 2.3 行业与市场分析（细化）

| 维度 | 内容 | 产出 | AI 辅助点 |
|------|------|------|-----------|
| **招投标/市场** | 采购方类型、高频需求、竞标项目 | 招投标需求清单、REQ 映射 | 招投标文本解析、需求抽取 |
| **行业痛点** | 用户侧痛点、影响程度、诉求 | 痛点清单、优先级 | 痛点分类、影响评估 |
| **竞品与政策** | 竞品能力、政策导向、技术趋势 | 竞品对标、政策摘要 | 竞品分析、政策解读 |

### 2.4 需求调研（一堂「需求里程碑」+ 精益「价值假设」）

| 验证维度 | 一堂四字诀 | 精益对应 | 验证方式 |
|----------|------------|----------|----------|
| **痛** | 需求强度 | 价值假设：用户是否认可 | 用户访谈、痛点排序 |
| **频** | 发生频率 | 使用频率是否足够 | 行为数据、问卷 |
| **量** | 用户规模 | 目标市场是否足够大 | 市场估算、TAM/SAM/SOM |
| **价** | 付费意愿 | 是否愿意付费 | 预付费测试、定价实验 |

### 2.5 产出

- 洞察报告（五维）
- 战略规划要点
- 行业分析报告
- 需求假设清单（待验证/已验证）
- Project Brief（项目简报）
- **L1 一级业务域**（顶层业务闭环）

## 三、Insight（洞察）— 业务需求与解决方案

### 3.1 业务需求类型（参考：BABOK、数字化转型框架）

| 类型 | 定义 | 数字化提升方向 |
|------|------|----------------|
| **运营提效** | 现有业务模式下，用更少资源达成更好结果 | 流程自动化、数据辅助决策、减少重复劳动 |
| **体验提升** | 改善用户/客户体验 | 响应更快、操作更简、服务更透明 |
| **新增业务** | 开拓新业务线、新场景、新收入 | 新触点、新能力、新商业模式 |
| **风险管控** | 合规、风控、质量、安全 | 校验、留痕、预警、审计 |
| **生态协同** | 与上下游、生态伙伴协作 | 对接、数据共享、联合运营 |

### 3.2 解决方案里程碑（一堂「解决方案」+ 精益 MVP）

| 维度 | 内容 | 产出 | 参考 |
|------|------|------|------|
| **解决的具体问题** | 针对哪些痛点、哪些用户 | 问题-方案映射 | BABOK |
| **差异化** | 与竞品的差异、独特价值 | 差异化陈述 | 波特五力 |
| **技术可行性** | 可实现性、依赖、风险 | 技术可行性评估 | - |
| **MVP 定义** | 最小可验证范围、核心功能 | MVP 范围、验收标准 | 精益创业 |

### 3.3 商业模式与增长（一堂「商业模式」「增长」— 参考商业模式画布）

- **短期**：先验证价值假设，商业模式可简化
- **中期**：单元模型（收入、成本、效率）
- **长期**：增长周期、壁垒（规模、网络效应、品牌）

### 3.4 产出

- 业务需求清单（运营提效、新增业务等）
- 解决方案文档
- MVP 范围与验收标准
- 用户旅程、角色
- **L2 二级业务流程**（功能模块）

## 四、Architecture（架构）— 数字化承载与规划

### 4.1 业务架构（L1/L2/L3/L4，参考：BIZBOK、TOGAF）

| 层级 | 定义 | 产出时机 | 参考框架 |
|------|------|----------|----------|
| **L1** | 一级业务域 | Discovery 完成 | BIZBOK 能力地图、战略地图 |
| **L2** | 二级模块/页面 | Insight 完成 | BIZBOK 价值流、举措地图 |
| **L3** | 三级业务动作 | Architecture 方案设计 | BABOK 需求分析 |
| **L4** | 四级业务步骤 | Launch 任务拆解 | 验收标准、AC |

**BIZBOK**：战略地图、能力地图、组织地图、价值流、信息地图、举措地图、产品地图、利益相关者地图  
**TOGAF**：业务架构 → 应用架构 → 数据架构 → 技术架构

### 4.2 数字化提升：运营提效 vs 新增业务

| 维度 | 数字化手段 | 参考 |
|------|------------|------|
| **运营提效** | 流程自动化、数据辅助决策、协同效率、减少重复劳动 | MIT 数字化转型九要素 |
| **新增业务** | 新触点、新能力（AI/算法）、新商业模式、新生态 | MIT 九要素、AWS 转型框架 |

### 4.3 技术架构与 Epic

- 技术栈、模块划分
- Epic 划分（Epic ↔ L2 映射）
- Story 拆解（Story ↔ L3 映射）
- L4 作为 AC 输入

### 4.4 短期 / 中期 / 长期规划（参考：数字化转型路线图）

| 时间维度 | 典型周期 | 聚焦 | 一堂对应 | 产出 |
|----------|----------|------|----------|------|
| **短期** | 1–3 个月 | MVP、价值验证、可演示 | 需求+解决方案 | 可投标/可演示版本 |
| **中期** | 3–6 个月 | 商业模式验证、核心闭环 | 商业模式 | 可运营、可复购 |
| **长期** | 6–12 个月+ | 增长、壁垒、规模化 | 增长+壁垒 | 可复制、护城河 |

**数字化转型路线图**：0–3 月快速见效 → 3–9 月扩展 → 9–18 月深化

### 4.5 产出

- 架构文档
- Epic、Story 列表
- 短中长期路线图
- 里程碑与交付物

## 五、Launch（交付）— 任务拆解与迭代

### 5.1 任务拆解规则

| 层级 | 拆解规则 | 粒度 |
|------|----------|------|
| **Epic → Story** | 按 L2 模块、用户价值拆分 | 1–2 周/Story |
| **Story → Task** | 按 L3 业务动作、技术模块拆分 | 0.5–2 天/Task |
| **Task 验收** | 对应 L4 步骤或 Given/When/Then | 可测试、可验收 |

### 5.2 AI 工具与 Vibe coding 应用

| 环节 | AI/Vibe 应用 | 说明 |
|------|--------------|------|
| **需求拆解** | AI 辅助将 REQ 拆为 Epic/Story | 提供上下文，AI 生成初稿 |
| **Task 生成** | 从 Story + L3 生成 Task 列表 | 自然语言描述，AI 拆解 |
| **代码实现** | Vibe coding、Cursor/Copilot | 对话式开发、快速原型 |
| **文档生成** | PRD、AC、变更说明 | AI 辅助起草、迭代 |
| **假设验证** | 数据分析、用户反馈汇总 | AI 总结、建议坚持/转向 |

### 5.3 精益 Build-Measure-Learn 循环

```
构建（Build）  →  测量（Measure）  →  学习（Learn）  →  坚持/转向
     │                    │                    │
  MVP/迭代交付        数据与反馈            决策：优化 or 调整
```

| 阶段 | 动作 | 产出 |
|------|------|------|
| **Build** | 按 Story/Task 实现、交付 MVP | 可演示、可测量 |
| **Measure** | 收集使用数据、用户反馈 | 指标、定性反馈 |
| **Learn** | 分析、判断假设是否验证 | 认知、决策 |
| **坚持/转向** | 继续优化 or 调整方案/用户/模式 | 下一轮迭代方向 |

### 5.4 产出

- 任务看板（Epic / Story / Task）
- 迭代交付物
- 验证报告（BML 学习记录）

## 七、AI 时代的不同

### 7.1 洞察层：AI 能做什么

| 环节 | 传统方式 | AI 时代 |
|------|----------|---------|
| **PESTEL 数据** | 人工搜集、阅读、整理 | AI 爬取、摘要、多源对比、趋势归纳 |
| **竞品分析** | 人工调研、报告 | AI 自动监测、竞品功能对比、舆情分析 |
| **SWOT 输出** | 研讨会、白板 | AI 基于结构化输入生成初稿、多方案对比 |
| **假设验证** | 问卷、访谈、手工统计 | AI 辅助分析、语义聚类、洞察抽取 |

### 7.2 战略与业务需求：AI 能做什么

| 环节 | 传统方式 | AI 时代 |
|------|----------|---------|
| **商业模式画布** | 人工填写、头脑风暴 | AI 生成初稿、多方案变体、行业对标 |
| **业务需求拆解** | 需求研讨会、逐条拆解 | AI 从 PRD/痛点 生成 REQ/Epic/Story 初稿 |
| **影响分析** | 人工追溯、Excel | AI 基于追溯矩阵做影响分析、依赖推荐 |
| **优先级排序** | 主观打分、拍板 | AI 基于数据与规则辅助排序、冲突检测 |

### 7.3 架构与交付：AI 能做什么

| 环节 | 传统方式 | AI 时代 |
|------|----------|---------|
| **架构设计** | 架构师画图、文档 | AI 辅助生成架构图、技术选型建议、依赖分析 |
| **Story ↔ Task** | 需求会、拆解会 | AI 从 Story + L3 生成 Task 列表、估算 |
| **代码实现** | 手写代码 | Vibe coding、Cursor/Copilot、Agent 协作（BMAD） |
| **文档与追溯** | 人工维护 | AI 自动同步、变更影响提示、追溯链补全 |

### 7.4 AI 时代的核心变化

| 维度 | 变化 |
|------|------|
| **速度** | 洞察→需求→拆解→交付的周期缩短，迭代更快 |
| **成本** | 信息搜集、初稿生成、重复劳动成本下降 |
| **人机分工** | 人负责决策、验证、把关；AI 负责生成、执行、汇总 |
| **上下文** | 结构化上下文（L1/L2/L3/L4、追溯矩阵）让 AI 更懂业务 |
| **可追溯** | 业务架构 + 追溯矩阵 = AI 可理解的「业务地图」 |
| **风险** | 需验证 AI 产出、避免幻觉、保持人的决策权 |

### 7.5 使用建议

- **结构化输入**：给 AI 提供 PESTEL 框架、SWOT 模板、L1/L2 结构，输出更稳定
- **迭代式生成**：AI 生成初稿 → 人复核修正 → 再喂回 AI 迭代
- **追溯链**：BAM 追溯矩阵让 AI 理解「改这里会影响哪里」
- **Agent 协作**：参考 BMAD，可配置 Analyst/PM/Architect 等角色 Agent
