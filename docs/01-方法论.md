## 一、统一流程

### 1.1 业务方向（下一步做什么）

```
洞察  →  战略规划  →  业务分解  →  差距与路径  →  任务拆解与实施
  │          │            │              │                │
五维分析   目标/MVP    L1→L2→L3→L4    现状vs目标       Epic→Story→Task
  │          │            │              │                │
  ↓          ↓            ↓              ↓                ↓
Discovery  Insight   Architecture     Architecture      Launch
```

**一句话**：先洞察，再定战略，再分解业务，再分析差距与路径，最后拆任务、执行迭代。

### 1.2 与 DIAL 四阶段对应

| 业务方向 | DIAL 阶段 | 产出 |
|----------|-----------|------|
| **洞察** | Discovery | L1、Project Brief、需求假设 |
| **战略规划** | Insight | L2、PRD、MVP、用户旅程 |
| **业务分解** | Architecture | L3/L4、Epic、Story、追溯链 |
| **差距与路径** | Architecture | 差距分析、短中长期路线图 |
| **任务拆解与实施** | Launch | Task、BML、交付物 |

**核心理念体现**：战略导向、流程分层、端到端追溯、闭环管理（参考华为）。

### 1.3 追溯链（BAM 核心）

```
REQ（需求）→ L1（一级域）→ L2（二级模块）→ Epic → Story → L3（业务动作）→ L4（业务步骤/AC）
```

| 层级 | 定义 | 产出阶段 |
|------|------|----------|
| **L1** | 一级业务域，顶层业务闭环 | Discovery |
| **L2** | 二级模块/页面，功能板块 | Insight |
| **L3** | 三级业务动作，用户可感知步骤 | Architecture |
| **L4** | 四级业务步骤，验收标准 | Launch |

## 三、与 BMAD 的协作

| 维度 | BMAD | DIAL-BAM |
|------|------|----------|
| **定位** | AI 驱动开发框架 | 业务分析及软件开发方法论 |
| **核心** | Agent、Workflow、Context 工程 | 发现、验证、规划、追溯 |
| **协作** | DIAL-BAM 做 Discovery/Insight/Architecture → BMAD 做 Phase 3/4 方案设计与实施 |

**使用建议**：纯方法论用 DIAL-BAM；有 Cursor/Copilot 可加 AI 辅助；已用 BMAD 可加 DIAL-BAM 补充发现与追溯。
