## 一、项目价值（Discovery：洞察）

### 1.1 核心价值主张

| 维度 | 内容 |
|------|------|
| **解决什么问题** | 传统方法割裂：需求分析、业务架构、开发交付各成体系，难以追溯 |
| **为谁解决** | 产品经理、项目经理、业务分析师、创业团队、ToB/ToG 项目 |
| **独特价值** | **核心理念 + 方法论 + 工具** 三位一体，参考华为，全链路可追溯，适配 AI 与 Vibe coding |

### 1.2 价值量化（痛频量价）

| 维度 | 分析 |
|------|------|
| **痛** | 需求散落、改一处不知影响、战略与执行脱节、方法论大杂烩 |
| **频** | 每个项目启动、需求变更、架构调整时都会遇到 |
| **量** | ToB/ToG、创业、数字化项目广泛存在 |
| **价** | 免费开源，降低采用门槛；企业可节省咨询费、统一内部方法 |

## 二、战略规划（Insight）

### 2.1 目标用户

| 用户 | 核心需求 |
|------|----------|
| **产品经理** | 从洞察到 PRD 的完整流程、需求追溯 |
| **项目经理** | 规划看板、Epic/Story 管理、BML 验证 |
| **业务分析师** | 业务分解、L1/L2/L3/L4、差距分析 |
| **创业团队** | 轻量、可裁剪、假设验证 |
| **企业** | 华为式流程、战略到执行、可落地工具 |

### 2.2 差异化

| 对比 | DIAL-BAM | 竞品/替代 |
|------|----------|-----------|
| **定位** | 业务分析 + 软件开发体系 | 单一框架（TOGAF 偏架构、BMAD 偏开发、精益偏验证） |
| **融合** | 华为 + 精益 + 一堂 + BMAD 深度融合 | 多为并列或单源 |
| **工具** | 核心理念→方法论→工具，配套 HTML 工具 | 多为文档/模板，少可视化 |
| **AI** | 结构化输入、AI Prompt 生成、可导入 | 多数未考虑 AI |
| **门槛** | 纯静态、无后端、npm init 即可用 | 部分需商业软件 |

### 2.3 商业模式（开源）

- **免费**：100% 开源，MIT 许可
- **价值**：品牌、社区、企业采用、潜在咨询/培训延伸

### 3.2 差距分析（现状 vs 目标）

| 差距 | 现状 | 目标 | 优先级 |
|------|------|------|--------|
| **多语言** | 仅 README_EN，工具全中文 | 英文版文档与工具 | P3 |
| **企业级案例** | 缺少标杆案例 | 1-2 个完整企业应用案例 | P2 |
| **认证体系** | 学习培训有考试，无正式认证 | 可选：轻量认证/徽章 | P3 |
| **生态集成** | 独立运行 | 与 BMAD、Notion、飞书等集成 | P3 |
| **移动端** | 部分响应式 | 全工具移动端优化 | P2 |
| **数据格式** | 各工具 JSON 格式独立 | 统一 Schema、跨工具导入导出 | P2 |
