## 一、业务流总览

```
核心理念（战略导向·流程分层·端到端追溯·闭环管理）
                    ↓
业务方向：洞察 → 战略规划 → 业务分解 → 差距与路径 → 任务与实施
                    ↓
DIAL 阶段：Discovery → Insight → Architecture → Launch
                    ↓
产出：L1/Project Brief | L2/PRD/MVP | Epic/Story/路线图 | Task/BML
```

### 1.1 业务流与 DIAL 对应

| 业务方向 | DIAL 阶段 | 产出 | 工具 |
|----------|-----------|------|------|
| 洞察 | Discovery | L1、Project Brief、需求假设 | 洞察可视化、痛点画布 |
| 战略规划 | Insight | L2、PRD、MVP | 商业模式画布 |
| 业务分解 | Architecture | Epic、Story、追溯链 | BAM 追溯矩阵 |
| 差距与路径 | Architecture | 路线图、里程碑 | 规划看板 |
| 任务与实施 | Launch | Task、BML 记录 | 规划看板、BML 验证看板 |

## 二、工具与数据流

```
洞察可视化 ──(洞察结论)──→ 痛点画布 ──(生成 BAM 初稿)──→ BAM 追溯矩阵
                                                              ↓
商业模式画布 ──(L2 输入)──→ BAM 追溯矩阵 ──(导入 Epic/Story)──→ 规划看板
                                                              ↓
                                                    BML 验证看板
                                                              ↓
                                             坚持/转向 ──(反馈)──→ 痛点画布
```

### 2.1 数据流说明

| 流向 | 数据格式 | 说明 |
|------|----------|------|
| 洞察 → 痛点 | 手动/导出 | 洞察结论作为痛点分析输入 |
| 痛点 → BAM | JSON | 「痛点画布生成初稿」生成 BAM 初稿 |
| BAM → 规划 | JSON | 「从 BAM 导入」填充 Epic/Story |
| 交付包 | JSON | 汇总各工具数据，一键导出/导入 |

## 三、企业诊断流程

### 3.1 顾问工作流

```
入场（访谈 + 五维洞察工作坊 + 痛点收集）
    ↓
Discovery：洞察可视化、痛点画布 → L1、Project Brief
    ↓
Insight：商业模式画布、差距分析 → L2、PRD、MVP
    ↓
Architecture：BAM、规划看板 → 短中长期路线图
    ↓
Launch：任务拆解、BML、坚持/转向决策
    ↓
顾问交付物：诊断报告、战略要点、路线图、BAM、BML 记录
```

### 3.2 工作坊设计

| 工作坊 | 时长 | 工具 | 产出 |
|--------|------|------|------|
| 战略与洞察 | 0.5–1 天 | 洞察可视化、痛点画布 | L1、Project Brief |
| 方案与 MVP | 0.5–1 天 | 商业模式画布 | L2、PRD |
| 差距与路径 | 0.5–1 天 | BAM、规划看板 | 路线图 |
| 执行与验证 | 持续 | BML 验证看板 | 迭代记录 |

## 四、BAM 追溯链

```
REQ（需求）→ L1（一级域）→ L2（二级模块）↔ Epic ↔ Story ↔ L3（业务动作）→ L4（业务步骤/AC）
```

| 层级 | 定义 | 产出阶段 |
|------|------|----------|
| REQ | 需求条目 | Discovery |
| L1 | 一级业务域 | Discovery |
| L2 | 二级模块 | Insight |
| Epic | 史诗 | Architecture |
| Story | 用户故事 | Architecture |
| L3 | 业务动作 | Architecture |
| L4 | 业务步骤/AC | Launch |

## 五、方法论与工具优化建议

### 5.1 已识别缺口（来自交付件清单）

| 缺口 | 当前状态 | 优化建议 |
|------|----------|----------|
| Project Brief | ✅ 已有工具 | [Project Brief 工具](../tools/Project-Brief.html) |
| PRD | ✅ 已有工具 | [PRD 模板工具](../tools/PRD-模板.html) |
| 交付件完整性检查 | ✅ 已实现 | 交付包导出页含完整性检查 |
| 洞察→痛点 数据联动 | ✅ 已实现 | 洞察可视化「推送到痛点画布」、痛点画布「从洞察导入」 |

### 5.2 工具链优化

| 优化项 | 说明 |
|--------|------|
| **一键数据流** | ✅ 洞察→痛点（推送到痛点画布）、痛点→BAM（前往 BAM 导入） |
| **交付包完整性检查** | 导出前检查：L1/L2 是否完整、追溯链是否连通 |
| **企业诊断模式** | 工具中心增加「企业诊断」入口，引导按工作坊顺序使用 |
| **角色引导** | 按角色（顾问/高管/产品/架构师）展示推荐工具路径 |

### 5.3 文档优化

| 优化项 | 说明 |
|--------|------|
| **业务流文档** | 本文档，与 [业务流可视化](../tools/业务流可视化.html) 配套 |
| **企业诊断指南** | 可独立成 doc，或并入学习培训体系 |
| **工具应用映射** | 在 [工具应用](工具应用.md) 中补充「数据流」与「企业诊断」章节 |

### 5.4 平台输入优化（来自平台输入与数据入口）

| 优化项 | 说明 |
|--------|------|
| **通用文件上传** | 支持 PDF、Word 上传，解析后作为洞察/需求输入 |
| **Excel 导入增强** | BAM、规划看板已支持，可补充「需求清单」模板 |
| **交付包导入** | ✅ 已支持「选择性导入」恢复指定工具 |
