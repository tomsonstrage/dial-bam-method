## 一、工具使用

### Q1：BAM 追溯矩阵无法加载数据？

**A**：请确保在项目根目录执行 `npm run serve` 后访问。若仍无法加载：
- 点击「加载示例」查看示例结构
- 或点击「导入 JSON」上传 BAM-追溯矩阵.json
- 数据会保存在浏览器 localStorage，刷新后仍可访问

### Q2：洞察/痛点画布的数据会丢失吗？

**A**：不会。数据自动保存在浏览器 localStorage，关闭页面后重新打开仍可看到。可随时「导出 JSON」备份。

### Q3：从 AI 获取的 BAM JSON 导入失败？

**A**：请检查：
1. AI 输出是否为纯 JSON（无 markdown 代码块包裹）
2. 若被 ```json 包裹，需先删除该部分再导入
3. 结构需包含 meta、L1、L2、requirements、epics、stories、L3 等字段

### Q4：规划看板导入 BAM 后没有 Story？

**A**：BAM 的 stories 通过 `epic` 字段关联到 epics。请确保 BAM JSON 中 stories 的 epic 与 epics 的 id 一致。

### Q4b：Project Brief、PRD 数据从哪里来？

**A**：Project Brief 可从痛点画布复制痛频量价、从 BAM 导入 L1。PRD 可从 BAM 导入 L2 功能清单。BAM 也可从 Project Brief 导入 L1。

### Q4c：交付包导入会覆盖现有数据吗？

**A**：会。导入会覆盖对应工具的 localStorage。若只想恢复部分工具，请使用「选择性导入」，勾选需要恢复的工具后再确认。

## 二、方法论

### Q5：DIAL 和 BAM 的关系？

**A**：DIAL 是流程（Discovery→Insight→Architecture→Launch），BAM 是追溯链（REQ↔L1↔L2↔Epic↔Story↔L3↔L4）。BAM 贯穿 DIAL 各阶段，实现端到端可追溯。

### Q6：最小可用的 BAM 结构是什么？

**A**：至少需要：一个 L1、一个 L2、REQ 与 L2 的映射。详见 [06 AI 增强与裁剪](06-AI增强与裁剪.md) 的「BAM 最小内核」。

### Q7：如何与 BMAD 配合使用？

**A**：DIAL-BAM 负责发现、规划、追溯；BMAD 负责开发与 Agent 协作。可先用 DIAL-BAM 产出 Epic/Story，再交给 BMAD 实施。详见 [与 BMAD 的关系](与BMAD的关系.md)。

## 三、部署与集成

### Q8：如何在自己的项目中复用？

**A**：两种方式：
1. 复制：`cp -r dial-bam-method/docs dial-bam-method/tools your-project/documents/`
2. 初始化：`npx dial-bam-method init`（或指定目录 `--directory=./my-docs`）

### Q9：工具可以离线使用吗？

**A**：可以。复制到本地后，除文档阅读（依赖 marked.js CDN）外，其他工具均可离线使用。若需完全离线，可将 marked.js 下载到本地引用。

### Q10：数据存储在哪里？

**A**：所有工具数据默认存储在浏览器 localStorage，不会上传到服务器。导出 JSON 后可自行保存到项目目录。
