# DIAL-BAM 内涵、外延、最小内核与可延伸

---

## 一、DIAL 方法论

### 1.1 内涵（Intension）

**核心定义**：在 AI 与 Vibe coding 环境下，将「发现→洞察→架构→交付」串成一条可执行、可验证的链路，用假设驱动替代愿景驱动。

**本质属性**：
- **假设驱动**：先验证再投入
- **闭环可测**：每阶段有可验证产出
- **AI 增强**：拆解、生成、分析由 AI 辅助，决策由人完成

### 1.2 外延（Extension）

**适用范围**：新业务/新产品 0→1、既有业务数字化、招投标、ToB/ToG、创业项目。

**边界**：不覆盖纯技术研究、无商业假设的探索；不覆盖成熟产品的日常运维。

### 1.3 最小内核（Minimum Kernel）

**不可删减的 4 要素**：

| 要素 | 含义 | 删掉会怎样 |
|------|------|------------|
| **假设** | 至少一个可验证假设（价值或增长） | 无法判断坚持/转向 |
| **MVP** | 明确的最小可验证范围 | 无法低成本验证 |
| **测量** | 可观测的指标或反馈 | BML 失效 |
| **决策点** | 坚持/转向的触发条件 | 无法闭环 |

**最小内核**：`假设 → MVP → 测量 → 决策（坚持/转向）`

### 1.4 可延伸（Extensible）

| 维度 | 可延伸内容 |
|------|------------|
| Discovery | 行业分析深度、需求验证方式 |
| Insight | 商业模式、单元模型 |
| Architecture | L3/L4、Epic/Story 粒度 |
| Launch | Task 粒度、AI 使用程度 |
| 规划 | 短期/中期/长期时间跨度 |

## 二、BAM 方法论

### 2.1 内涵（Intension）

**核心定义**：用业务架构把 BMAD 的开发流程结构化，使业务域、模块、动作、步骤与需求、Epic、Story、AC 一一对应，实现可追溯。

**本质属性**：双向追溯、层级映射、产出链。

### 2.2 外延（Extension）

**适用范围**：需需求追溯的项目、多模块协作、长期维护产品。

**边界**：不覆盖一次性脚本、个人小工具、无业务结构的纯技术项目。

### 2.3 最小内核（Minimum Kernel）

**不可删减的 3 要素**：

| 要素 | 含义 | 删掉会怎样 |
|------|------|------------|
| **业务域** | 至少一个 L1 | 无法界定范围 |
| **模块** | 至少一个 L2 | 无法落需求 |
| **映射** | REQ 与 L2 对应 | 无法追溯 |

**最小内核**：`L1（业务域）→ L2（模块）→ REQ 映射`

### 2.4 可延伸（Extensible）

| 维度 | 可延伸内容 |
|------|------------|
| 层级 | L3、L4 |
| 开发流程 | Epic、Story |
| 工具 | 追溯矩阵、检查清单 |
| 角色 | 多角色分工 |

---

## 三、DIAL 与 BAM 的关系

| 维度 | DIAL | BAM |
|------|------|-----|
| **内涵** | 假设驱动的发现→交付全流程 | 业务架构驱动的追溯体系 |
| **外延** | 新业务、数字化、创业、招投标 | 需追溯、多模块、长期维护 |
| **最小内核** | 假设 + MVP + 测量 + 决策 | L1 + L2 + REQ 映射 |
| **可延伸** | 行业分析、商业模式、规划、AI、BML | L3/L4、Epic/Story、工具、多角色 |

**组合建议**：
- 新项目/创业：从 DIAL 最小内核起步，再按需加 BAM
- 已有需求、需追溯：从 BAM 最小内核起步，再按需加 DIAL 的 Discovery/Insight
- 大型/长期项目：完整 DIAL + BAM
