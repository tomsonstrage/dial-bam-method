## 二、需求分析（历史背景）

> 以下为规划阶段的需求分析，**实际完成以第七节为准**。

### 2.1 用户故事（按优先级）

| 优先级 | 用户故事 | 验收标准 |
|--------|----------|----------|
| **P1** | 作为产品经理，我能在 BAM 追溯矩阵中直接编辑 L1/L2/REQ/Epic/Story/L3/L4，以便无需手写 JSON | 支持增删改、保存为 JSON 下载或覆盖本地文件（若环境允许） |
| **P1** | 作为产品经理，我能从洞察可视化导出结构化数据，并导入到 BAM 或需求假设，以便打通 Discovery→Insight 数据流 | 洞察导出格式与 BAM/需求假设兼容，或提供「导入到 BAM」入口 |
| **P2** | 作为产品经理，我能使用商业模式画布工具填写并导出，以便完成 Insight 阶段的战略产出 | 新增商业模式画布 HTML 工具，支持 9 宫格填写、导出、AI 提示词 |
| **P2** | 作为项目经理，我能使用规划与任务看板，将 Epic/Story/Task 可视化并关联 BAM，以便管理短中长期规划 | 新增规划看板或增强 DIAL 规划模板为可交互工具 |
| **P2** | 作为用户，我能在工具中心直接阅读文档内容，而不必下载 .md 文件 | 文档以 HTML 或 Markdown 渲染页展示 |
| **P3** | 作为产品经理，我能使用痛点画布（痛频量价）工具，以便 Discovery 阶段产出需求假设 | 新增痛点/需求假设画布 |
| **P3** | 作为团队，我们能使用 BML（Build-Measure-Learn）验证看板，以便 Launch 阶段做坚持/转向决策 | 新增 BML 验证工具 |
| **P3** | 作为开发者，init 能完整复制所有文档与指导文档子目录 | COPY_MAP 补全 |

### 2.2 非功能需求

| 维度 | 需求 |
|------|------|
| **兼容性** | 保持纯静态、无后端，可 `npx serve` 或任意静态托管 |
| **数据** | 优先 localStorage + 导出 JSON，避免依赖后端 |
| **AI 友好** | 结构化数据便于复制为 AI 提示词，未来可扩展 API 调用 |
| **可裁剪** | 新工具可独立使用，不强制依赖其他工具 |

## 三、开发计划（历史路线图）

> 以下为规划阶段的 Phase 1–4 路线图，**实际完成以第七节为准**。

### Phase 1：BAM 可编辑与数据闭环（2–3 周）

**目标**：BAM 追溯矩阵支持编辑，洞察数据可导入 BAM/需求。

| 任务 | 说明 | 产出 |
|------|------|------|
| 1.1 BAM 矩阵可编辑 | 表格内支持行内编辑、新增行、删除行 | 编辑后可「导出 JSON」覆盖 BAM-追溯矩阵.json |
| 1.2 BAM 导入 JSON | 支持从本地上传 JSON 文件加载 | 降低初始化门槛 |
| 1.3 洞察→需求映射 | 洞察导出增加「需求假设/REQ 初稿」结构，或提供「生成 BAM 初稿」AI 提示词 | 打通 Discovery→Architecture |
| 1.4 工具中心入口 | 在工具中心增加「从洞察生成需求」的引导或链接 | 流程引导 |

**里程碑**：用户可在 BAM 界面完成全链路编辑，并导出 JSON 保存。

## 四、技术选型建议

| 场景 | 建议 | 理由 |
|------|------|------|
| Markdown 渲染 | marked.js + 简单 HTML 包装 | 轻量、无构建、CDN 即可 |
| BAM 编辑 | 原生 JS + contenteditable 或 input | 保持无框架，与现有风格一致 |
| 数据持久化 | localStorage + 导出 JSON | 无后端，用户自管数据 |
| 文件上传 | `<input type="file">` | 纯前端，用于 BAM 导入 JSON |

---

## 五、优先级与建议执行顺序

```
建议优先：Phase 1（BAM 可编辑） → Phase 2（商业模式画布） → Phase 3（文档展示）
可选延后：Phase 4（痛点画布、BML）
```

**理由**：
- BAM 可编辑是当前最大痛点，直接影响日常使用
- 商业模式画布在文档中多次提及，补齐后方法论更完整
- 文档展示与 init 补全成本低、收益明显

## 六、风险与依赖

| 风险 | 缓解 |
|------|------|
| BAM 编辑逻辑复杂 | 先做「行级编辑 + 导出」，再考虑高级功能 |
| 多工具数据格式不统一 | 定义轻量 JSON Schema，各工具遵循 |
| 无后端导致「保存到文件」受限 | 明确以「导出 JSON + 用户手动替换」为主流程 |
