## 一、AI 时代的变化

### 1.1 洞察与战略

| 传统 | AI 时代 |
|------|---------|
| 人工搜集 PESTEL 数据 | AI 爬取、摘要、多源对比、趋势归纳 |
| 人工竞品调研 | AI 自动监测、功能对比、舆情分析 |
| 研讨会产出 SWOT | AI 基于结构化输入生成初稿、多方案 |
| 手写商业模式画布 | AI 生成初稿、行业对标、变体探索 |
| 问卷、访谈、手工统计 | AI 辅助分析、语义聚类、洞察抽取 |

### 1.2 业务需求与架构

| 传统 | AI 时代 |
|------|---------|
| 需求会逐条拆解 | AI 从 PRD/痛点 生成 REQ/Epic/Story 初稿 |
| 人工维护追溯 | AI 基于追溯矩阵做影响分析、依赖推荐 |
| 架构师画图 | AI 辅助生成架构图、技术选型建议 |
| 需求会拆 Task | AI 从 Story + L3 生成 Task 列表、估算 |

### 1.3 交付与迭代

| 传统 | AI 时代 |
|------|---------|
| 手写代码 | Vibe coding、Cursor、Copilot、Agent 协作 |
| 人工写 PRD/AC | AI 辅助起草、迭代 |
| 人工分析 BML 数据 | AI 总结、建议坚持/转向 |

### 1.4 核心变化与风险

| 维度 | 变化 |
|------|------|
| **速度** | 洞察→交付周期缩短，迭代更快 |
| **成本** | 信息搜集、初稿生成、重复劳动成本下降 |
| **人机分工** | 人负责决策、验证、把关；AI 负责生成、执行、汇总 |
| **上下文** | L1/L2/L3/L4、追溯矩阵 = AI 可理解的「业务地图」 |
| **风险** | 需验证 AI 产出、避免幻觉、保持人的决策权 |

### 1.5 使用建议

- **结构化输入**：给 AI 提供 PESTEL 框架、SWOT 模板、L1/L2 结构，输出更稳定
- **迭代式生成**：AI 生成初稿 → 人复核修正 → 再喂回 AI 迭代
- **追溯链**：BAM 追溯矩阵让 AI 理解「改这里会影响哪里」
- **Agent 协作**：参考 BMAD，可配置 Analyst/PM/Architect 等角色 Agent

## 二、最小内核与裁剪

### 2.1 DIAL 最小内核

**不可删减 4 要素**：`假设 → MVP → 测量 → 决策（坚持/转向）`

| 要素 | 含义 | 删掉会怎样 |
|------|------|------------|
| **假设** | 至少一个可验证假设（价值或增长） | 无法判断坚持/转向 |
| **MVP** | 明确的最小可验证范围 | 无法低成本验证 |
| **测量** | 可观测的指标或反馈 | BML 失效 |
| **决策点** | 坚持/转向的触发条件 | 无法闭环 |

### 2.2 BAM 最小内核

**不可删减 3 要素**：`L1（业务域）→ L2（模块）→ REQ 映射`

| 要素 | 含义 | 删掉会怎样 |
|------|------|------------|
| **业务域** | 至少一个 L1 | 无法界定范围 |
| **模块** | 至少一个 L2 | 无法落需求 |
| **映射** | REQ 与 L2 对应 | 无法追溯 |

### 2.3 适用边界

| DIAL | BAM |
|------|-----|
| **适用**：新业务 0→1、数字化、招投标、ToB/ToG、创业 | **适用**：需追溯、多模块、长期维护 |
| **不适用**：纯技术研究、无商业假设；成熟产品日常运维 | **不适用**：一次性脚本、个人小工具、无业务结构 |

### 2.4 组合建议

- **新项目/创业**：从 DIAL 最小内核起步，再按需加 BAM
- **已有需求、需追溯**：从 BAM 最小内核起步，再按需加 Discovery/Insight
- **大型/长期项目**：完整 DIAL + BAM

### 2.5 可延伸维度

| 维度 | 可延伸内容 |
|------|------------|
| Discovery | 行业分析深度、需求验证方式 |
| Insight | 商业模式、单元模型 |
| Architecture | L3/L4、Epic/Story 粒度 |
| Launch | Task 粒度、AI 使用程度 |
| 规划 | 短期/中期/长期时间跨度 |
| BAM | L3、L4、Epic、Story、追溯矩阵、多角色 |
