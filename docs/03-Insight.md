## 一、业务需求类型

**参考**：BABOK、数字化转型框架

| 类型 | 定义 | 数字化提升方向 |
|------|------|----------------|
| **运营提效** | 用更少资源达成更好结果 | 流程自动化、数据辅助决策、减少重复劳动 |
| **体验提升** | 改善用户/客户体验 | 响应更快、操作更简、服务更透明 |
| **新增业务** | 开拓新业务线、新场景、新收入 | 新触点、新能力、新商业模式 |
| **风险管控** | 合规、风控、质量、安全 | 校验、留痕、预警、审计 |
| **生态协同** | 与上下游、生态伙伴协作 | 对接、数据共享、联合运营 |

### 1.1 业务需求类型选择

| 场景 | 建议类型 | 数字化重点 |
|------|----------|------------|
| 降本增效 | 运营提效 | 流程自动化、RPA、BI |
| 提升 NPS | 体验提升 | 响应速度、自助服务 |
| 新业务线 | 新增业务 | 新系统、新触点 |
| 合规审计 | 风险管控 | 留痕、预警、审计 |
| 生态合作 | 生态协同 | 接口、数据共享 |

## 二、解决方案里程碑

**参考**：一堂「解决方案」、精益 MVP

| 维度 | 内容 | 产出 |
|------|------|------|
| **解决的具体问题** | 针对哪些痛点、哪些用户 | 问题-方案映射 |
| **差异化** | 与竞品的差异、独特价值 | 差异化陈述 |
| **技术可行性** | 可实现性、依赖、风险 | 技术可行性评估 |
| **MVP 定义** | 最小可验证范围、核心功能 | MVP 范围、验收标准 |

### 2.1 解决方案评估步骤

1. **问题-方案映射**：每个痛点对应 1–N 个方案
2. **差异化陈述**：与竞品对比，3 条核心差异
3. **技术可行性**：技术栈、依赖、风险、工期估算
4. **MVP 范围**：只做「验证核心假设」的最小功能集

### 2.2 MVP 定义模板

| 维度 | 内容 |
|------|------|
| 核心假设 | 要验证的价值/增长假设 |
| 核心功能 | 3–5 个必须功能 |
| 排除项 | 明确不做什么 |
| 验收标准 | 可测量、可演示 |

## 三、商业模式与增长

**参考**：商业模式画布、一堂「商业模式」「增长」

- **短期**：先验证价值假设，商业模式可简化
- **中期**：单元模型（收入、成本、效率）
- **长期**：增长周期、壁垒（规模、网络效应、品牌）

### 3.1 用户旅程要素

| 要素 | 说明 |
|------|------|
| 角色 | 用户/客户类型 |
| 旅程阶段 | 认知→考虑→购买→使用→复购 |
| 触点 | 每个阶段的接触点 |
| 痛点/机会 | 该阶段的改进点 |

## 四、产出与 BAM 衔接

| 产出 | 说明 |
|------|------|
| 业务需求清单 | 运营提效、新增业务等 |
| 解决方案文档 | 问题-方案映射、差异化 |
| MVP 范围与验收标准 | 最小可验证范围 |
| 用户旅程、角色 | 用户视角 |
| **L2 二级业务流程** | 功能模块，进入 BAM 追溯链 |

### 4.1 L2 定义示例

| L2 编号 | 二级模块 | 归属 L1 | 说明 |
|---------|----------|---------|------|
| L2-01-01 | 线索管理 | L1-01 | 线索录入、分配、跟进 |
| L2-01-02 | 商机管理 | L1-01 | 商机阶段、预测、赢单 |
| L2-02-01 | 工单处理 | L1-02 | 工单创建、分配、关闭 |

### 4.2 PRD 核心章节

- 业务背景、目标用户
- 功能清单（与 L2 对应）
- 用户旅程、角色
- MVP 范围与验收标准
- 非功能需求（性能、安全）

**工具**：[PRD 模板](../tools/PRD-模板.html) 结构化填写，支持从 BAM 导入 L2 功能清单。

**检查清单**：业务需求类型明确（提效/新增）、MVP 范围明确、**L2 已定义**
