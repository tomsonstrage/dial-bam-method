## 一、任务拆解规则

| 层级 | 拆解规则 | 粒度 |
|------|----------|------|
| **Epic → Story** | 按 L2 模块、用户价值拆分 | 1–2 周/Story |
| **Story → Task** | 按 L3 业务动作、技术模块拆分 | 0.5–2 天/Task |
| **Task 验收** | 对应 L4 步骤或 Given/When/Then | 可测试、可验收 |

### 1.1 任务拆解步骤

1. **Epic → Story**：按 L2 模块、用户价值拆分，每 Story 1–2 周
2. **Story → Task**：按 L3 动作、技术模块拆分，每 Task 0.5–2 天
3. **Task 验收**：写 Given/When/Then 或对应 L4 步骤

### 1.2 Task 验收标准模板（Given/When/Then）

```
Given 用户已登录且处于 [页面/状态]
When 用户 [执行动作，如点击保存]
Then [预期结果 1]
And [预期结果 2]
```

### 1.3 L4 → AC 映射示例

| L4 步骤 | AC（验收标准） |
|--------|----------------|
| 选择「选项A」 | Given 用户在选择页，When 选择选项A，Then 显示确认 |
| 点击保存 | Given 表单已填写，When 点击保存，Then 数据持久化且提示成功 |

## 三、Build-Measure-Learn 循环

```
构建（Build）  →  测量（Measure）  →  学习（Learn）  →  坚持/转向
     │                    │                    │
  MVP/迭代交付        数据与反馈            决策：优化 or 调整
```

| 阶段 | 动作 | 产出 |
|------|------|------|
| **Build** | 按 Story/Task 实现、交付 MVP | 可演示、可测量 |
| **Measure** | 收集使用数据、用户反馈 | 指标、定性反馈 |
| **Learn** | 分析、判断假设是否验证 | 认知、决策 |
| **坚持/转向** | 继续优化 or 调整方案/用户/模式 | 下一轮迭代方向 |

### 3.1 BML 各阶段具体动作

| 阶段 | 具体动作 | 工具/方法 |
|------|----------|-----------|
| **Build** | 按 Story 实现、部署、发布 | 看板、CI/CD |
| **Measure** | 埋点、日志、问卷、访谈 | 分析工具、用户反馈 |
| **Learn** | 数据分析、假设验证判断 | 周会、复盘 |
| **坚持/转向** | 决策会、调整 backlog | 优先级重排 |

### 3.2 坚持/转向决策点

| 触发条件 | 动作 |
|----------|------|
| 核心指标达标 | 坚持，扩大范围 |
| 核心指标不达标 | 转向，调整方案/用户/模式 |
| 新认知 | 更新假设，下一轮验证 |
