## 一、业务分解（L1/L2/L3/L4）

**参考**：BIZBOK、TOGAF

| 层级 | 定义 | 产出时机 |
|------|------|----------|
| **L1** | 一级业务域 | Discovery 完成 |
| **L2** | 二级模块/页面 | Insight 完成 |
| **L3** | 三级业务动作，用户可感知步骤 | Architecture 方案设计 |
| **L4** | 四级业务步骤，验收标准 | Launch 任务拆解 |

**映射规则**：REQ → L1 → L2 ↔ Epic ↔ Story ↔ L3 → L4 → AC

### 1.1 L3/L4 拆解规则

| 层级 | 拆解原则 | 示例 |
|------|----------|------|
| **L3** | 用户可感知的原子动作 | 「选择场景」「填写表单」「提交审批」 |
| **L4** | 具体选项、分支、步骤 | 「选择选项A」「点击保存」「选择审批人」 |

### 1.2 华为流程分层对应

| 华为 | DIAL-BAM |
|------|----------|
| 流程 L1（主流程） | L1 一级业务域 |
| 流程 L2（子流程） | L2 二级模块 |
| 流程 L3（活动） | L3 业务动作 |
| 流程 L4（任务） | L4 业务步骤 |

## 三、技术架构与 Epic

- 技术栈、模块划分
- **Epic 划分**：Epic ↔ L2 映射
- **Story 拆解**：Story ↔ L3 映射
- **L4 作为 AC 输入**

### 3.1 Epic 划分步骤

1. 按 L2 模块逐一对应，一个 L2 可拆 1–N 个 Epic
2. Epic 命名：`[L2 名称] - [用户价值]`，如「商机管理 - 阶段推进」
3. 建立 Epic ↔ L2 映射表

### 3.2 Story 拆解模板

| 字段 | 说明 |
|------|------|
| 标题 | 作为 [角色]，我想 [动作]，以便 [价值] |
| 归属 Epic | Epic ID |
| 对应 L3 | L3 编号 |
| 验收标准 | Given/When/Then 或 L4 步骤 |

### 3.3 技术架构要素

- 技术栈（前端、后端、数据库、中间件）
- 模块划分、接口定义
- 部署架构、环境

## 四、差距分析与路径分析

**参考**：华为「分析→战略规划→差距分析→路径分析」

### 4.1 差距分析

| 步骤 | 内容 | 产出 |
|------|------|------|
| 1. 现状盘点 | 当前能力、系统、流程、组织 | 现状清单 |
| 2. 目标对照 | 战略规划中的目标、L1/L2 要求 | 目标清单 |
| 3. 差距识别 | 现状 vs 目标，逐项对比 | 差距清单、优先级 |
| 4. 根因分析 | 关键差距的根因 | 改进方向 |

### 4.2 路径分析

| 步骤 | 内容 | 产出 |
|------|------|------|
| 1. 演进路径 | 如何从现状到目标，分阶段 | 路径图 |
| 2. 里程碑 | 各阶段关键交付物、验收标准 | 里程碑清单 |
| 3. 依赖与资源 | 依赖关系、资源需求 | 依赖图、资源计划 |

## 五、短期 / 中期 / 长期规划

**参考**：数字化转型路线图、一堂五步

| 时间维度 | 典型周期 | 聚焦 | 产出 |
|----------|----------|------|------|
| **短期** | 1–3 个月 | MVP、价值验证、可演示 | 可投标/可演示版本 |
| **中期** | 3–6 个月 | 商业模式验证、核心闭环 | 可运营、可复购 |
| **长期** | 6–12 个月+ | 增长、壁垒、规模化 | 可复制、护城河 |

**路线图**：0–3 月快速见效 → 3–9 月扩展 → 9–18 月深化

### 5.1 路线图规划步骤

1. **短期**：列出 MVP 必须功能，拆为 1–3 个月可交付里程碑
2. **中期**：商业模式验证所需功能，3–6 个月
3. **长期**：增长、壁垒相关能力，6–12 个月+
4. 标注依赖关系、资源需求

### 5.2 里程碑模板

| 里程碑 | 时间 | 交付物 | 验收标准 |
|--------|------|--------|----------|
| M1 | 第 1 月 | 核心流程可演示 | 可演示、可测量 |
| M2 | 第 3 月 | MVP 上线 | 用户可试用 |
| M3 | 第 6 月 | 商业模式验证 | 有付费/复购 |
